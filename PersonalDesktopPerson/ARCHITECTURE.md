# Runtime architecture
OpenCode → Personal Person MCP (identity/state/memory/goals/approval) → delegation envelope → Computer-use MCP (screen/accessibility/input) → verified result → `record_experience`.

The cognitive pulse is independent of prompts and runs at configurable frequency. Appraisal impulses and bounded decay update continuous dimensions and derived modes. Intention arbitration gives pending approval precedence, then an approved active goal, then quiet availability. SQLite WAL stores events and FTS retrieval. Immutable identity statements are separated from owner-editable interests/style.

The safety governor classifies action proposals R0–R4. Under conservative policy only R0 is automatic. The runtime has no shell, filesystem, screen, input, credential, or network tool beyond a configured model endpoint. Computer control remains a separate revocable capability.
